## Plan B：uni-app 小程序重构（PC 作为服务端，手机运行未发布小程序）

> 适用前提：**课程/评审明确要求用 uni-app 的“未发布小程序”演示**，并认为 `his-mp-webview`（患者端 web-view 壳）不足以满足要求。

> 目标：在不改动后端微服务与 Gateway 的前提下，新增一个基于 uni-app（`mp-weixin`）的患者端小程序，实现**可演示的核心链路**：
>
> **登录 → 在线挂号 → 我的挂号 → 个人中心（退出/查看基础信息）**
>
> 并在本机/演示 PC + 手机（同一局域网）条件下跑通。

> 如果你只是为了“在微信开发者工具内演示患者端”，不需要走 Plan B 的 uni-app 重构：直接参照 `frontend/his-mp-webview/README.md` 使用 web-view 壳即可。

### B.1 目标与边界

**目标（本 Plan B 的 Definition of Done）**

- 新建 `frontend/his-uni-patient` uni-app 项目，编译目标为 `mp-weixin`
- 小程序端完成以下页面（最小集合，优先保证联调通畅）：
  - 登录页（token 保存）
  - 首页（入口卡片）
  - 在线挂号页（选择科室 → 选择医生/号源 → 提交挂号）
  - 我的挂号页（展示当日/历史挂号列表）
  - 个人中心页（显示基础信息 + 退出登录）
- 手机访问后端：通过 Gateway 的 HTTP API（PC 作为服务端）
- 文档补齐：uni-app 启动/真机调试步骤（写进 `docs/演示说明.md` 或本节）

**非目标（本阶段不做）**

- 全量页面迁移（账单/报告/随访等非核心演示页默认不做或延后）
- 上架审核、生产域名/HTTPS 正式配置（开发/演示环境下按“本地不校验/调试”处理）
- 复杂的消息订阅、推送等（演示可先不覆盖）

### B.2 关键技术选择

- **uni-app**：Vue 3 模式（或官方推荐 ts 模板）
- **组件库**：优先使用 `uni-ui`（减少 UI 返工；也可只用基础 uni 组件）
- **网络层封装**：
  - 封装 `request.ts`：统一请求、超时、loading、错误码 Toast
  - 将 `baseURL` 从环境变量注入，避免硬编码
- **鉴权**：
  - 登录成功后写入 `uni.setStorageSync('token')` 与 `userId`
  - 全局拦截（路由守卫或请求拦截）自动携带 `Authorization: Bearer <token>`

### B.3 重构范围与现有页面映射

| 功能 | H5（现有） | uni-app（新增） | 说明 |
|------|------------|------------------|------|
| 登录 | `frontend/his-web-patient/src/views/Login.vue` | `pages/auth/login.vue` | 保存 token + userId |
| 首页 | `frontend/his-web-patient/src/views/Home.vue` | `pages/home/index.vue` | 快捷入口为“挂号/我的挂号/个人中心” |
| 在线挂号 | `views/registration/Registration.vue` | `pages/registration/index.vue` | 选择科室/医生/号源 → 提交挂号 |
| 我的挂号 | `views/appointment/MyAppointments.vue` | `pages/appointment/list.vue` | 查询当前 patient 的挂号记录 |

### B.3.1 uni-app 请求路径与参数映射（从现有 H5 `src/api/*` 迁移）

> 约定：uni-app `baseURL` 设置为 `http://<PC_LAN_IP>:8080`（Gateway 端口），并在请求中使用 `/api/...` 前缀。

| 业务 | H5 API（现有） | uni-app 调用路径（等价） | 请求参数要点 |
|------|------------------|---------------------------|----------------|
| 登录 | `authApi.login()`：`POST /auth/login`（axios baseURL=`/api`） | `POST http://<PC_LAN_IP>:8080/api/auth/login` | body：`{ username, password }`；返回：`accessToken / refreshToken / userId ...` |
| 获取号源 | `scheduleApi.getSlotsByDate(departmentId,date)`：`GET /schedule/slots?departmentId=...&date=...` | `GET http://<PC_LAN_IP>:8080/api/schedule/slots?departmentId=...&date=YYYY-MM-DD` | `departmentId` 来自科室选择；`date` 选择的就诊日期 |
| 发起挂号 | `registrationApi.register()`：`POST /registration/register` | `POST http://<PC_LAN_IP>:8080/api/registration/register` | body：`{ patientId, scheduleId, cardType, visitDate, doctorId }` |
| 我的挂号列表 | `registrationApi.getRegistrations()`：`GET /registration/list?patientId=...&page=...&pageSize=...` | `GET http://<PC_LAN_IP>:8080/api/registration/list?patientId=...&page=1&pageSize=10` | `patientId` 来自登录后的 `userId`；page/pageSize 默认第一页即可 |
| 取消挂号 | `registrationApi.cancelRegistration(id)`：`PUT /registration/{id}/cancel` | `PUT http://<PC_LAN_IP>:8080/api/registration/{id}/cancel` | `{ id }` 为 registration 记录 id |
| 个人信息（个人中心） | `authApi.getUserInfo(userId)`：`GET /users/{userId}` | `GET http://<PC_LAN_IP>:8080/api/users/{userId}` | 用登录后的 `userId` 拉取基础信息 |
| 科室列表（两步走） | 当前 H5 `Registration.vue`：科室为前端硬编码 | **Step1（快速可演示）**：仍硬编码 10 科室，与 `backend/go/sql/demo_data.sql` 对齐 | Step1：保证演示可跑通 |
|  | `his-web-admin`：`departmentApi.getList()`：`GET /departments`（可作为后续替换） | `GET http://<PC_LAN_IP>:8080/api/departments` | Step2：替换 hardcode（按 status=1、level 取根/一层） |

> 小心点：`MyAppointments.vue` 在现有仓库里对 `registrationApi.getRegistrations` 的参数传递存在不一致风险。uni-app 重构时建议统一实现一个包装函数：`getRegistrations(patientId, page=1, pageSize=10)`，避免对象/位置参数混用导致请求参数错误。

| 风险 | 影响 | 应对 |
|------|------|------|
| HTTP/域名限制导致真机调试失败 | 手机端无法请求 API | 开发工具优先“本地不校验”；必要时引入 HTTPS 隧道（后续计划） |
| 页面迁移过大导致延期 | 演示验收失败 | 严格控制范围：只做 4～5 页，UI 简化优先保证链路 |
| uni-app 的组件/布局差异 | UI 不一致或出现空白 | 先做功能通，再做样式微调 |
| API 形态在 uni-app 与 H5 间差异 | 请求/响应适配成本 | 复用现有 H5 的 API 模型与字段命名，必要时做 DTO 转换 |

### B.7 触发 Plan B 的“启动条件”

当满足以下任意条件时再启用本 Plan B：

- 课程/评审明确要求“uni-app 小程序形态演示”（且 web-view 壳不被接受）
- 当前可演示路径因“演示口径”受阻（例如必须在微信小程序运行环境中展示）
- 你们有至少 1 人可以连续投入约 1 周完成核心链路迁移
