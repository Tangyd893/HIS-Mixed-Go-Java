## 五、关键问题与风险

### 5.1 架构/设计问题
| 问题 | 影响 | 解决方案 |
|------|------|----------|
| Go Dockerfile无法支持多服务 | 无法正确运行多个Go服务 | 为每个服务单独构建或使用符号链接/命令分发 |
| Java Dockerfile的jar覆盖 | 服务互相覆盖无法区分 | 为每个服务单独构建或使用不同文件名 |
| 端口映射不一致 | 部署配置混乱 | 统一README与docker-compose端口定义 |
| Go服务未初始化基础设施 | 服务无法连接数据库/Redis/MQ | 补充main.go初始化逻辑 |
| Go服务gRPC未注册实现 | 无法处理gRPC请求 | 实现并注册gRPC Service |

### 5.2 缺失的关键组件
| 组件 | 重要性 | 说明 |
|------|--------|------|
| Go服务repository层 | 高 | service和model之间缺少数据访问层 |
| Go服务gRPC handler | 高 | 未实现proto定义的Service接口 |
| Proto生成代码 | 高 | `.pb.go`和Java stub均未生成 |
| Java业务代码 | 高 | 9个服务无任何Entity/Mapper/Service/Controller |
| 前端管理端 | 中 | 目录完全不存在 |
| Nacos Go SDK集成 | 中 | README提到但代码中未实现 |
| RabbitMQ Consumer | 中 | 仅有Publisher封装，无Consumer端 |

### 5.3 技术债务
- Go服务main.go缺少优雅关闭（graceful shutdown）
- 缺少健康检查端点的实际实现
- 缺少配置热更新机制
- 缺少日志级别动态调整
- 缺少链路追踪集成（OpenTelemetry）
