# HIS-Mixed 项目架构设计文档

> 基于 Java + Go 混合架构的全链路医院信息系统（HIS）重构方案

---

## 一、项目概述

本项目是对原 Hospital-Information-System（Spring Cloud Alibaba + Vue.js）的 **Java + Go 混合架构重构版本**。全链路医院信息系统（HIS），覆盖**院内诊疗流程**与**院外患者服务**两大核心板块。系统采用前后端分离的微服务架构，让 Java 和 Go **各司其职、高效协作**：Go 负责高并发 I/O 密集型场景，Java 负责复杂业务逻辑与事务一致性，所有服务统一通过 Docker 进行容器化部署与管理。

### 1.1 重构目标

- 将原单体 Java 项目拆分为**18 个微服务模块**，按业务特征分配给 Java 和 Go 两种语言
- Go 网关替代 Spring Cloud Gateway，预期 QPS 提升 5-10 倍，内存降低 70%
- 挂号、药房、检查等高频服务用 Go 实现，充分利用协程模型处理并发
- 复杂业务（门诊、处方、收费、住院、EMR）保留在 Java Spring Boot 生态
- 通过 gRPC 实现跨语言同步调用，RabbitMQ 实现异步解耦
- 共享 proto 文件作为唯一 API 契约，保证接口一致性
- 高频数据（号源、排队状态）通过 Redis 缓存，保证系统响应速度

### 1.2 设计原则

| 原则 | 说明 |
| ---- | ---- |
| 各取所长 | Go 负责高并发 I/O 场景，Java 负责复杂事务与业务逻辑 |
| 服务自治 | 各微服务独立开发、独立部署、独立扩展 |
| 契约优先 | proto 文件作为跨语言唯一 API 契约 |
| 异步解耦 | 高并发写入（Go）与复杂事务持久化（Java）通过 MQ 分离 |
| 高可用 | 关键服务多副本部署，数据库主从架构 |
| 高性能 | Redis 缓存高频数据，RabbitMQ 异步削峰填谷 |
| 可观测性 | 全链路日志追踪、指标监控、告警体系 |

**关键协作模式**：
- **同步调用**（gRPC）：Java 服务调用 Go 服务（如校验号源），Go 服务调用 Java 服务（如查询患者信息）
- **异步协作**（MQ）：Go 服务处理高并发写入并推送消息，Java 服务消费消息完成复杂事务持久化
- **服务发现**：所有服务（Go + Java）统一注册至 Nacos，互相发现

## 三、技术栈分配策略

### 3.1 核心原则

| 原则 | 说明 |
| ---- | ---- |
| **Go 负责** | 高并发 I/O、网关、缓存、消息队列消费者 |
| **Java 负责** | 复杂业务逻辑、事务、数据一致性 |

### 3.2 详细分配表

| 模块类型 | 具体服务 | 推荐技术栈 | 核心理由 |
| -------- | -------- | ---------- | -------- |
| **网关层** | Gateway | **Go (Gin)** | 高并发连接、JWT 验证、限流、路由转发 — Go 协程模型优势明显 |
| **认证授权** | Auth | **Java (Spring Security)** | JWT 签发/刷新、RBAC 权限矩阵复杂、与业务数据强关联 |
| **基础数据** | User/Department | **Java (Spring Boot)** | 数据一致性强，多表关联复杂 |
| **高并发交易** | Registration (挂号) | **Go (Gin + Redis)** | 号源扣减高并发，Redis 分布式锁 — Go 并发性能好 |
| **复杂业务** | Clinic (门诊) | **Java (Spring Boot)** | 复杂诊断逻辑、事务边界长 |
| **医疗核心** | EMR (电子病历) | **Java (Spring Boot)** | SOAP 结构化、模板引擎、三级质控 — Java 生态有成熟方案 |
| **处方管理** | Prescription | **Java (Spring Boot)** | 状态流转复杂，与 Billing 强事务关联 |
| **收费结算** | Billing | **Java (Spring Boot) + Seata** | 分布式事务核心，与医保接口对接 — Java 事务生态成熟 |
| **药房库存** | Pharmacy | **Go (Gin + GORM)** | 库存扣减高并发，定期效期检查 (cron) |
| **检查检验** | Examination | **Go (Gin)** | 与设备对接偏 I/O 型，并发高 |
| **住院管理** | Inpatient | **Java (Spring Boot)** | 医嘱、护理、结算等复杂状态机 |
| **排班管理** | Schedule | **Go (Gin + Redis)** | 号源生成大量写操作，乐观锁 |
| **院外服务** | Outpatient | **Go (Gin)** | 在线问诊高并发，WebSocket 实时通信 — Go 原生支持更好 |
| **随访管理** | Follow-up | **Go (Gin)** | 定时任务多，逻辑相对独立 |
| **健康档案** | Health Record | **Java (Spring Boot)** | 数据聚合复杂，多服务调用 |
| **通知服务** | Notification | **Go (Gin)** | 发送短信/邮件是 I/O 密集型 |
| **统计报表** | Statistics | **Go (Gin)** | 数据量大，聚合计算，可用 Go 并发处理 |
| **系统管理** | System | **Java (Spring Boot)** | 字典、参数配置，与认证权限关联 |

### 3.3 统计数据

- **Go 服务**：9 个 (Gateway、Registration、Pharmacy、Examination、Schedule、Outpatient、Follow-up、Notification、Statistics)
- **Java 服务**：9 个 (Auth、User、Clinic、EMR、Prescription、Billing、Inpatient、Health Record、System)

## 五、跨语言通信设计

### 5.1 gRPC 同步调用

proto 文件作为 Java 和 Go 的**唯一 API 契约**，双方共享同一份 proto 定义。

**目录结构**：

```

├── common/
│   └── common.proto           # 公共消息类型（分页、错误、用户上下文）
├── registration/
│   └── registration.proto     # 挂号服务
├── pharmacy/
│   └── pharmacy.proto         # 药房服务
├── schedule/
│   └── schedule.proto         # 排班服务
├── ...                        # 其他服务 proto
```

**gRPC 阻塞调用示例** (Go 挂号服务):

```go
// backend/go/internal/registration/service/registration.go
func (s *RegistrationService) RegisterAppointment(
    ctx context.Context,
    req *pb.RegisterRequest,
) (*pb.RegisterResponse, error) {
    // Redis 分布式锁扣减号源
    lockKey := fmt.Sprintf("schedule_lock:%d", req.ScheduleId)
    if !s.redis.AcquireLock(ctx, lockKey, 30*time.Second) {
        return nil, status.Error(codes.ResourceExhausted, "系统繁忙")
    }
    defer s.redis.ReleaseLock(ctx, lockKey)

    // 扣减库存
    remaining := s.redis.DecrStock(ctx, req.ScheduleId)
    if remaining < 0 {
        return nil, status.Error(codes.NotFound, "号源已约满")
    }

    // 生成挂号 ID
    registrationID := s.idGen.NextID()

    // 发送消息给 Java 服务（通过 MQ 异步持久化）
    msg := &AppointmentMessage{
        RegistrationId: registrationID,
        PatientId:      req.PatientId,
        ScheduleId:     req.ScheduleId,
        Status:         "registered",
    }
    s.mq.Publish(ctx, "registration.created", msg)

    return &pb.RegisterResponse{
        RegistrationId: registrationID,
        Status:         "success",
        QueueNumber:    remaining + 1,
    }, nil
}
```

### 5.2 RabbitMQ 异步协作

| 场景 | 生产者 | 消费者 | 交换机类型 |
| ---- | ------ | ------ | ---------- |
| 挂号成功通知 | Go (Registration) | Java (持久化) + Go (Notification) | Topic |
| 处方状态变更 | Java (Prescription) | Go (Notification / Pharmacy) | Topic |
| 检查报告发布通知 | Go (Examination) | Go (Notification) | Direct |
| 排队叫号更新 | Go (Registration) | Go (客户端推送) | Fanout |
| 住院费用日清单 | Java (Inpatient) | Go (Notification) | Direct |
| 随访任务分发 | Go (Follow-up) | Go (Notification) | Direct |
| 慢病异常告警 | Go (Outpatient) | Go (Notification) | Topic |
| 操作审计日志 | 全部服务 | Java (System) | Fanout |

**Java 端消费示例** (挂号消息持久化):

```java
// backend/java/shared/consumer/src/main/java/.../consumer/RegistrationConsumer.java
@Component
public class RegistrationConsumer {
    @Autowired
    private RegistrationRepository registrationRepository;

    @RabbitListener(queues = "registration.queue")
    @Transactional
    public void handleAppointmentCreated(AppointmentMessage msg) {
        // 写入 PostgreSQL — Java 擅长的事务操作
        Registration registration = new Registration();
        registration.setId(msg.getRegistrationId());
        registration.setPatientId(msg.getPatientId());
        registration.setScheduleId(msg.getScheduleId());
        registration.setStatus(msg.getStatus());
        registrationRepository.save(registration);

        // 更新患者最后就诊时间
        patientRepository.updateLastVisit(msg.getPatientId(), LocalDateTime.now());
    }
}
```

### 5.3 Nacos 统一服务发现

Java 和 Go 服务统一注册到 Nacos：

- **Java 端**：使用 `spring-cloud-starter-alibaba-nacos-discovery`
- **Go 端**：使用 Nacos Go SDK (社区版)
- 双方通过 Nacos 发现对方服务地址，gRPC 客户端直连调用

## 七、RabbitMQ 消息可靠性设计

### 7.1 三大保障策略

#### 7.1.1 生产者可靠发送

1. **本地消息表（Transactional Outbox 模式）**：
   - 业务数据与消息记录写入同一数据库事务
   - 消息状态：`待发送(0)` → `已发送(1)` → `消费成功(2)` / `消费失败(3)`
2. **Publisher Confirm（发布确认）**：
   - 启用 RabbitMQ 发布确认模式
   - Go 端通过 `amqp.Confirmation` channel 异步接收确认
   - Java 端通过 Spring AMQP `setPublisherConfirmType(CORRELATED)`
3. **定时补偿**：
   - Cron 定时扫描"待发送"超时消息，重试投递
   - Go 端使用 `robfig/cron`，Java 端使用 `@Scheduled`
4. **重试策略**：自动重试 3 次，间隔递增（2s/5s/10s），超过后转入死信表

#### 7.1.2 防止消息丢失

1. **持久化**：交换机、队列、消息均设置 `durable=true`
2. **Quorum Queue**：使用 RabbitMQ Quorum Queue 基于 Raft 协议保证消息不丢
3. **消费者手动确认（Manual ACK）**：
   - Go 端：`autoAck=false`，业务成功后 `msg.Ack(false)`
   - Java 端：`spring.rabbitmq.listener.simple.acknowledge-mode=manual`
4. **消费失败重试与死信队列**：
   - 重试 3 次，间隔 3s/10s/30s
   - 超过重试上限后路由至死信队列（DLQ），人工处理

#### 7.1.3 防止重复消费（幂等性）

1. **消息唯一标识**：每条消息携带全局唯一 ID（雪花算法生成）
2. **数据库唯一约束**：消息记录表 `msg_id` 字段建立唯一索引
3. **Redis 防重标记**：`SETNX msg:consumed:{msgId} 1 EX 86400`
4. **业务幂等**：
   - 挂号扣减号源：Redis `DECR` 原子操作 + 分布式锁
   - 处方状态更新：乐观锁（`version` 字段 + `WHERE version = ?`）
   - 收费状态变更：业务流水号（`billNo`）幂等判断

## 九、安全设计

### 9.1 认证鉴权流程

```
用户登录 → Go Gateway 转发 → Java Auth 服务验证
                                  │
                                  ├── 验证通过 → 签发 JWT Token (RS256)
                                  │               → Token 存入 Redis（支持主动失效）
                                  │               → 返回用户信息 + 权限列表
                                  │
                                  └── 验证失败 → 返回 401
```

- **JWT 签名算法**：RS256（非对称加密）
- **Token 有效期**：Access Token 2 小时，Refresh Token 7 天
- **Token 存储**：Redis，支持服务端主动失效
- **Gateway 权限校验**：
  - 白名单路径（登录/注册/健康检查）直接放行
  - 其他请求在 Gateway 层解析 JWT，注入用户上下文
  - 通过 gRPC metadata / HTTP Header 透明传递至下游

### 9.2 安全措施

- JWT 密钥对通过环境变量注入，禁止硬编码
- 敏感字段（手机号、身份证号）写入日志前需脱敏
- 生产环境启用 HTTPS（Nginx 终结 TLS）
- 数据库密码、Redis 密码等通过 Kubernetes Secrets 管理
- 操作审计日志统一收集至 Java System 服务
- CORS 白名单在 Gateway 层统一配置

### 11.1 院内诊疗流程

```
患者挂号(Go) → 分诊叫号(Go) → 医生接诊(Java) → 检查/检验申请(Java)
                │                      │
                │              ┌───────┴────────┐
                │              │ 处方开具/审核    │
                │              │   (Java)        │
                │              └───────┬────────┘
                │                      │
                └──────────────────────┼────────── 收费结算(Java) ── 药房发药(Go)
                                       │                      │
                                       └──── 住院(Java)（入院/护理/出院）
```

### 11.2 典型跨语言调用场景

**挂号场景**：
1. 用户发起挂号请求 → Go Gateway JWT 验证 → 转发至 Go Registration 服务
2. Go Registration：Redis 分布式锁扣减号源 → 雪花算法生成挂号 ID
3. Go Registration → RabbitMQ 发送"挂号成功"消息
4. Java Registration Consumer：消费消息 → 写入 PostgreSQL 持久化 → 更新患者信息
5. Go Notification：消费消息 → 发送短信/推送通知
