# HIS-Mixed MVP演示说明

## 一、演示环境准备

### 1.1 启动基础设施
```bash
# 启动数据库和中间件
cd docker
docker-compose up -d postgresql redis rabbitmq nacos minio
```

### 1.2 初始化数据库
```bash
# 推荐：使用仓库脚本（迁移 + 种子 + 分库演示数据）
cd scripts/db
chmod +x db_init.sh
./db_init.sh
```

> `db_init.sh` 会：创建 17 库 → 执行 migrations → 灌入 `seed_data.sql`、`demo_user_data.sql`、`demo_registration_data.sql`、`demo_schedule_data.sql` 等。  
> 数据库连接默认：`localhost:15432`，用户 `his_admin`（与 Docker Compose 映射一致）。

### 1.3 启动后端服务

**推荐：一键脚本**
```bash
# 最小演示集（Gateway + auth/user + registration/schedule/statistics + 双前端）
./scripts/start_demo.sh

# 含 pharmacy 等扩展服务
FULL_MODE=true ./scripts/start_demo.sh

# 可选：健康检查
./scripts/verify_demo.sh
```

**手工启动（最小集）**
```bash
cd backend/go
go run cmd/gateway/main.go &
go run cmd/registration/main.go &
go run cmd/schedule/main.go &
go run cmd/statistics/main.go &

cd ../java
mvn spring-boot:run -pl his-auth &
mvn spring-boot:run -pl his-user &
```

> 最小演示服务集：Gateway + his-auth + his-user + registration + schedule + statistics。  
> **药品管理页**需额外启动 pharmacy（`:8087`），或使用 `FULL_MODE=true ./scripts/start_demo.sh`。  
> **处方/费用页**（患者端）：Gateway 已配置 `/pharmacy/prescriptions`、`/billing/bill-items` 等路由；需 `FULL_MODE=true` 启动 pharmacy 及 his-billing 等对应服务。

### 1.4 启动前端应用
```bash
# 患者端 (端口5174)
cd frontend/his-web-patient
npm run dev

# 管理端 (端口5175)
cd frontend/his-web-admin
npm run dev
```

### 1.5 （可选）微信开发者工具演示患者端

> `frontend/his-mp-webview` 仅服务于患者端演示壳，不包含管理端业务。

1. 先完成 1.1~1.4，确保 `his-web-patient` 可在 `http://127.0.0.1:5174` 打开。
2. 打开微信开发者工具，导入目录：`frontend/his-mp-webview`。
3. 进入 **详情 → 本地设置**，勾选：
   - 不校验合法域名、web-view（业务域名）、TLS 版本及 HTTPS 证书。
4. 编译后应直接进入患者端页面（web-view 内加载 H5）。

真机预览补充：
- 将 `frontend/his-mp-webview/pages/index/index.js` 中 `DEFAULT_PATIENT_H5` 改为 `http://<PC局域网IP>:5174`。
- `his-web-patient` 需以可被局域网访问方式启动（如 `npm run dev -- --host`）。
- `touristappid` 主要用于本机工具演示；真机受限时需替换为可用测试号/正式 AppID 并具备体验成员权限。

## 三、演示流程

### 3.1 管理端演示（http://localhost:5175）

#### 步骤1：管理员登录
1. 访问 http://localhost:5175
2. 输入账号 `admin` / `admin123`
3. 点击登录

#### 步骤2：查看工作台
- 查看今日统计数据（挂号数、就诊数、处方数、收入）
- 查看最近挂号记录
- 使用快捷操作按钮

#### 步骤3：医生管理
1. 点击左侧菜单"业务管理" → "医生管理"
2. 查看医生列表（5位医生）
3. 演示功能：
   - 搜索：按姓名/科室筛选
   - 新增：点击"新增医生"按钮
   - 编辑：点击"编辑"修改医生信息
   - 状态切换：启用/停用医生

#### 步骤4：排班管理
1. 点击左侧菜单"排班管理"
2. 查看排班列表
3. 演示功能：
   - 查看排班：按医生、科室、日期筛选
   - 新增排班：点击"新增排班"
   - 批量排班：点击"批量排班"，设置日期范围和时段

#### 步骤5：药品管理
1. 点击左侧菜单"药品管理"
2. 查看药品列表（10种药品）
3. 演示功能：
   - 搜索：按药品名称/编码筛选
   - 新增：点击"新增药品"
   - 库存调整：点击"库存"进行入库/出库操作
   - 查看库存预警（库存低于最低库存时显示警告）

#### 步骤6：患者管理
1. 点击左侧菜单"患者管理"
2. 查看患者列表
3. 点击"详情"查看患者完整信息

#### 步骤7：系统管理
1. 科室管理：查看科室树形结构
2. 用户管理：查看系统用户列表

## 六、常见问题

### Q1: 登录失败
**A**: 检查后端服务是否启动，至少包含 Gateway、his-auth、his-user；再检查账号数据是否已导入（见 1.2）。

### Q2: 数据为空
**A**: 检查是否执行了演示数据脚本

### Q3: 页面无法访问
**A**: 检查前端服务是否启动，端口是否正确（患者端5174，管理端5175）

### Q4: API请求失败
**A**: 检查网关服务是否启动（8080），并确认对应业务服务已启动（如挂号需 registration/schedule，管理端统计需 statistics）。

### Q5: 微信开发者工具里白屏/无法打开
**A**:
1. 确认 `frontend/his-web-patient` 已启动（`http://127.0.0.1:5174` 可在浏览器访问）。
2. 确认微信开发者工具已勾选“不校验合法域名、web-view、TLS...”。
3. 真机预览时不要使用 `127.0.0.1`，改为 PC 局域网 IP，并检查防火墙放行 5174 端口。
4. 若真机仍受限，检查 AppID/体验成员权限（`touristappid` 可能受限制）。

## 七、演示脚本（快速启动）

### 7.1 推荐：使用仓库脚本

**Linux / macOS / Git Bash：**

```bash
./scripts/start_demo.sh
```

**Windows（PowerShell，需已安装 Docker Desktop、Go、Node、Maven）：**

```powershell
# 若 bash 可用（Git Bash / WSL）
bash ./scripts/start_demo.sh

# 或按 §1.1～1.4 分步手工启动
```

> `scripts/start_demo.sh` 已包含：Docker 基础设施、数据库初始化、最小后端服务、双前端启动，并在末尾提示导入 `frontend/his-mp-webview`。  
> 药品页等扩展能力：`FULL_MODE=true ./scripts/start_demo.sh`。  
> 启动后可用 `./scripts/verify_demo.sh` 检查各端口（见 §1.6）。

### 7.2 手工方式（示例）

```bash
#!/bin/bash
# 一键启动演示环境

# 1. 启动基础设施
cd docker && docker-compose up -d postgresql redis rabbitmq nacos minio

# 2. 等待数据库就绪
sleep 5

# 3. 初始化数据库
cd ../backend/go
./scripts/db_init.sh

# 4. 启动后端服务
go run cmd/gateway/main.go &
go run cmd/registration/main.go &
go run cmd/schedule/main.go &
go run cmd/pharmacy/main.go &
go run cmd/statistics/main.go &
cd ../java
mvn spring-boot:run -pl his-auth &
mvn spring-boot:run -pl his-user &

# 5. 启动前端
cd ../../frontend/his-web-patient && npm run dev &
cd ../his-web-admin && npm run dev &

echo "演示环境启动完成！"
echo "患者端: http://localhost:5174"
echo "管理端: http://localhost:5175"
```
